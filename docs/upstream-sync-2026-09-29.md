## 第一批：历史分页与首屏请求

提交：`8b1556b`（`Port stable history pagination and combined thread bootstrap`）。

上游解码后 `server.js` 的关键依据：

- `sliceCodexHistoryWindow`（10415 行附近）固定首页的消息总量，避免新内容追加使 offset 分页漂移。
- `handleThreadBootstrap`（13200 行附近）合并首屏的 status 和 history。
- `codexHistoryVersionFromStat` / `unchangedCodexHistoryResult`（10372 行附近）使用文件版本和 `ifVersion`。这是历史接口的应用层条件读取，不能等同于本地已有 HTTP ETag 支持。

本地读取的是 App Server 原生协议，因此不复制 JSONL 的 offset/base 算法：

1. `thread/turns/list` 按原生游标读取。将已取轮次中的未显示消息暂存为分页快照，每页默认返回最多 5 条；向前加载不再重读最新窗口。
2. 给消息增加稳定 ID，前端只向顶部插入新取得的旧消息，保留原有节点、活跃回复及滚动位置。插入期间使用即时滚动，避免平滑滚动干扰位置补偿。
3. 游标绑定任务与页大小，重试返回同一结果；最多保留 24 个分页记录，15 分钟过期。过期返回 410，网页重新取得最近 5 条。
4. 工具事件占满的历史允许返回空页及后续游标，每次最多读取 5 页原生轮次，避免为了凑满可见消息扫描整个任务。
5. 新增 `/codex/thread-bootstrap`，首屏一次 HTTP 返回历史、状态、队列和审批。历史和状态共享最新轮次读取；正常打开一个任务的相关 HTTP 请求从 4 次降为 1 次，配置、健康检查和任务列表仍分别获取。
6. 保留反序列化失败时的 JSONL 恢复路径及其累计窗口加载方式。原生分页游标错误不降级成另一套分页结果。

本批没有引入跨请求的状态缓存，避免让发送结果、队列或审批变陈旧。历史版本短路、图片缩略图、状态原子持久化仍需按本地数据源分别设计。

## 第二批：发布包排除私有运行状态

- 遍历待打包目录时，提前剪除任意层级的 `.mimosa` 目录，也排除同名文件；大小写按 Windows 环境兼容处理。
- ZIP 校验再次检查所有路径片段，阻止显式清单或其他收集方式将该目录带入包中。
- 测试覆盖 `public`、`lib`、`relay-server` 的嵌套目录、同名文件、大小写及反斜杠路径。
- 本地检查时没有发现该目录；这是补上打包边界，不是已发生泄漏的结论。
