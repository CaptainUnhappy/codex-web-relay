# 后续计划：跨端提问统一确认

状态：现有原生卡片的目标仍未完成，缺少可调用的 App 异步问题确认入口。用户另行授权的统一提问服务隔离原型已完成（见文末），尚未替换正式流程。图片预览与 Goal 控件已独立交付。

2026-10-19 展示口径修正：用户已选择将无法确认当前状态的 App 历史问题收进默认折叠的“历史提问”，标记状态未确认。正式 Web 不再把历史问题放入当前 approvals。这项降级展示不代表原生卡片同步完成，见 [验收记录](../validation/question-history-state-boundary-2026-10-19.md)。

## 目标与已知事实

让手机回答 Codex App 的异步问题后，App 卡片同步关闭，且不能再提交同一问题。现有原生 `item/tool/requestUserInput` 可在 Web 回答；Desktop 的 `request_user_input_async` 由 App 本地卡片提交回调确认，普通消息包装不能代替该动作。

已经保留 App 单入口保护；用户人工验收卡片关闭，回查只有一次回答。详见 `../validation/desktop-question-single-entry-2026-10-18.md`。

## 执行顺序

1. 已补充复现 App 历史观察器差异：同 turn 外部答案会更新 lastSubmission，但不收起所选面板；新 turn 答案不回溯旧问题。证据与可执行只读脚本见验证记录。继续需要 App 提供以 thread/question ID 提交并确认的入口，或源代码层面的协调修复。
2. 若接口存在，在隔离测试对话接入它，保证提交幂等、结果未知时不重放。没有接口则保留只读卡片，不改 App 私有内存、数据库或 rollout。
3. 双向验收：手机答一次后 App 不可再答；App 答一次后手机不可再答；刷新、离线重连、重复点击均只有一条答案，卡片状态一致。
4. 核验无会话强制占用，完整回归后仅本地提交。

## 交付闸门

不能只凭模型回显或普通消息去重判定完成。必须同时有原始问题确认、两端 UI 关闭、单条持久答案三类证据。当前 App 已打开界面的跨进程 Goal 即时刷新也可在该阶段做只读验证，但不与问题确认接口混为一谈。

## 已定位的 App 修复位置与必须保留的行为

原生 `app-initial` 的 `mIt` 需在应用已接受的答案后，像 `A$e` 一样重新计算所选问题剩余集合；没有未回答或尚未提交的本地修改时，统一收起面板。答案索引还需跨 turn 按稳定 question ID 关联，处理模型结束后才收到的回答。提交入口需拒绝或幂等返回已确认的问题，不能单靠页面收起阻止双击/旧客户端重放。存在未提交草稿时应保留草稿并提示已在另一端回答，避免悄悄丢弃输入。

这些改动属于 App 源码/协议的能力，目前 Mini 仓库不拥有该入口。禁止把离线复现通过记作跨端验收通过；当前继续保留临时单入口保护，等待可用的正式接口或 App 源码修复条件。

## 用户提出的共享 Server 方案（已调查）

新增证据见 `../validation/shared-app-server-feasibility-2026-10-18.md`。普通 Windows App 存在内部 WS 启动入口，真实原生 Server 的双客户端请求确认和去重已实测通过；但它针对原生请求 ID。Desktop 异步回答包装作为普通消息时，同一个 Server 仍接受两条相同答案，当前 App 原函数也仍保留所选卡片。

因此共享 Server 可作为后续基础工程，不能替代原目标的卡片确认修复。实施前需验证 App 的认证/工具接入并改造 Mini 释放语义；只有这些条件与真正的异步问题确认同时满足，才进入双向 UI 验收。本轮未切换现有服务配置。

## 独立统一提问服务原型（已授权并完成）

实现保存在 `codex/unified-question-prototype` 分支的 `lib/question-service-prototype/`。手机模拟视口与桌面浏览器使用相同问题状态，服务端原子确认和单调快照使两端收起已答入口；9 个问题产生 9 条答案，包含同时提交、重复点击、响应丢失、断线、刷新及服务重启场景。

具体证据与下一阶段条件见 [隔离原型验收](../validation/unified-question-prototype-2026-10-18.md)。该原型没有接入或修复已有 App 原生卡片，也没有切换现有服务。后续路线是注册独立提问工具并在隔离 Codex 会话验证结果投递，需用户决定后再启动。

## 真实 App 工具接入（已授权并完成隔离验收）

专用测试对话已实际调用项目级 MCP，手机模拟视口回答后，App 内浏览器中的独立卡片同步收起回答控件。模型可见的答案工具结果为 1 条；刻意重复工具调用返回 `already_claimed` 且无答案正文。临时项目配置和信任已还原，未切换正式服务。

详见 [真实 App 验收与下一阶段条件](../validation/unified-question-app-tool-2026-10-18.md)。下一阶段为多问题绑定、取消/超时/不确定投递核对及受信 HTTPS 下的实体手机验收，等待用户决定。旧原生异步卡片仍保持 App 单入口保护。
