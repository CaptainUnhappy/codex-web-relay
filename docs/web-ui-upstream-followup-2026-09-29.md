## 本轮实现及根因

### 任务导航

原来只有项目分组与展开按钮，缺少搜索。每次刷新直接替换整个列表，控件焦点会随旧节点一起丢失。现在保留搜索输入节点，只更新结果区，按稳定任务/项目标识恢复焦点和滚动位置。

- 搜索已加载的任务名或项目名，支持组合关键词、大小写不敏感和子任务；显示搜索范围，保留“加载更多会话”。不会自动拉取全部历史。
- 搜索临时展开相关项目，清除搜索后恢复原收起状态。
- 键盘打开后进入搜索框，方向键选择任务，Escape 关闭手机列表并返回标题；Tab 离开列表时收起手机浮层，让下一控件的焦点可见。
- 任务、项目与分页行至少 44 像素高；保持桌面常驻侧栏，手机提供关闭按钮。
- 减少动画偏好同时覆盖消息、滚动及输入区过渡。任务按钮的提示保留名称/项目，不再使用内部路径代替标题。

### 静态传输

原来的 HTML 使用 `no-store`，刷新必然重传完整页面。从官方解码 `server.js` 的 `staticBodyEtag`、`getStaticFileEntry`、`getStaticResponseBody`、`staticCacheControlForExt`（13405–13479 行附近）适配为 `lib/static-assets.js`。

- 对可压缩且超过 1 KB 的静态内容提供 gzip，尊重 `gzip;q=0`，设置 `Vary: Accept-Encoding`。
- 使用跨编码弱 ETag，内容未变时返回 304；HEAD 保留对应 GET 的长度且不发送正文。
- 缓存最多 32 项、原始与压缩内容合计 8 MiB，文件签名变化会重新读取。
- 保留令牌 Cookie 行为；所有静态资源使用私有、每次校验缓存。API 的 `no-store` 不变。
- 中继原来无条件把 `Content-Length` 设为实际传回的正文长度，导致 HEAD/304 被写为 0；本轮同步修正这一完整链路。

### 状态保存

原来直接 `writeFileSync(STATE_FILE, ...)` 会先截断旧文件，中途失败可能让后续读取退回空状态。参考官方 `writeCodexMiniStateFileAtomically`（1876–1911 行附近），改为同目录独占临时文件、写入、fsync、关闭、原子替换。

失败时清理临时文件并向调用方抛错，保留旧状态；只有保存成功才失效列表缓存。不采用先删旧文件再重命名的补丁。本轮不修复既有损坏文件，也不提供跨进程读改写事务。
