# Web 会话释放与交互验收（2026-10-18）

本轮范围：单会话手动/自动归还、列表缓存、Git 工作树项目归并、两个明确的新建入口、手机列表与输入区切换。仅本地提交，不推送。

## 结果

- 默认在回复完成后空闲 60 秒自动释放；支持 0、60、300、900 秒，设置可持久保存。运行中的回复、审批和结果不明确的写操作不会自动切断。
- 归还会关闭 Mini 持有写入权的 App Server 进程。只读列表、历史与状态不延长写入占用，也不会自动接管已归还的会话。公网中继连接继续提供手机访问。
- 列表复用 30 秒快照，手动刷新可绕过缓存。发送和队列调度只检查目标会话，不再扫描 100 个历史会话。
- 项目归属沿 Git `gitdir` / `commondir` 查找，Windows 路径格式统一；保留每条对话原始工作目录，不按文件夹名称猜测归并。
- 顶栏新建入口已移除。项目栏新建使用所选项目，对话栏新建无项目对话；首次发送前是本地草稿，不占用桌面。
- 手机浮层展开时隐藏输入区和顶部切换控件；关闭后草稿恢复。桌面固定侧栏保留输入区。

## 实测发现并修复的根因

1. 旧进程运行状态缓存会残留 `running`，阻止再次接管后的自动释放。现在依据新进程 resume 返回的真实状态更新非 live 缓存。
2. 新线程刚启动时，原生存储短暂返回空 rollout 或 `list_turns is not supported yet`。仅当前持有者的实时事件可用于弥补该间隙，其他错误仍然返回，外部或过期缓存不能假装实时结果。
3. 每次发送及队列调度扫描 100 个历史会话，在真实数据量下曾超时 45 秒。现在仅刷新目标会话；全局列表失败不阻塞发送、队列继续和释放。
4. 文字新建按钮沿用旧图标网格，导致文字挤成竖排；已改为完整文字布局。
5. 新草稿沿用旧历史分页入口；现在清除分页状态，并隔离迟到的历史响应。

独立审查覆盖所有权、队列、缓存、项目归并与 UI 状态。对“未知发送结果应恢复可重发草稿”的建议未直接采纳：发送内容仍保留在消息气泡，现有结果未知保护用于避免重复发送。
