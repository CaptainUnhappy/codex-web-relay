# 会话导航缓存与自动补页验收（2026-10-18）

## 问题与处理

原始接口按最近活动读取原生线程页，再筛选为项目/对话。前端把已收到的线程归入项目；展开某一类别只增大显示区域，没有自动补页。列表仅存在当前页面内存中，网页重载后重新从第一页开始。

本轮保留原生数据源、项目路径归一化和两个类别独立游标，新增：

- 按设备隔离的浏览器列表缓存：已加载会话元信息、项目归属、分页位置、项目展开状态、当前分栏方式和滚动位置。最近一次保存超过 7 天的快照不恢复。
- 先验证当前设备身份，再恢复缓存并更新最新一页。缓存不保存会话正文、运行状态、turn ID 或队列状态，避免把旧执行状态当成实时状态。
- 可见区域不足或滚动到距底部 100px 内时，自动读取对应类别的后续页；隐藏类别、关闭的浮动菜单、后台页面、搜索模式和限流冷却期间不启动自动补读。
- 空的分类页仍可沿有效游标继续；每批自动读取至多十轮，连续失败或游标不前进时保留手动加载入口。单次读取失败可延迟 1.5 秒重试一次。
- 新记录超过一页时先补齐新旧快照之间的缺口，再接回原来的旧记录游标。过期游标（400/410）只重启一次，并保留已有内容。服务端返回完整类别时会替换该类别快照，移除已不存在的缓存记录。
- 最新页刷新与加载更多并发时，加载更多会等待刷新后继续，不会被吞掉；最新页成功也不会抹去旧页加载失败的重试状态。退出登录后迟到的身份请求不能重新启用缓存。

缓存对象是已经读取的项目/会话导航列表。更早、尚未读取的项目仍随原生分页逐步出现；本轮没有增加全账户目录扫描，也没有一次性下载全部消息正文。
