# 输入框可见区域与统一底部留白

日期：2026-10-20。用户确认越界主要发生在键盘弹出或收起后。

## 结果

- 普通、键盘打开及 standalone 模式共享 `max(8px, env(safe-area-inset-bottom))`：基础留白为 8px；设备安全区更大时保留安全区，不把按钮压进系统手势区。
- 输入框定位始终依据实际可见区域，不再以输入焦点或“大于 80px 的高度缩小”作为校正位置的前提。
- 失焦后继续跟随仍在收起的键盘；同步事件处理后在下一帧再读取一次最终几何。
- 移除额外的 CSS 位移动画，避免网页动画落后于浏览器键盘动画；没有增加周期轮询。

## 复现与根因

新增 `scripts/test-composer-viewport-ui.js` 加载生产 HTML，在独立浏览器上下文中模拟 `visualViewport` 的高度、偏移和事件，保留真实 DOM、focus/blur、CSS 和动画帧。

修复前稳定复现：

1. 可见高度仍为 500px 时 textarea 失焦，旧逻辑立即清空位移。关闭动画后输入框底边到达 834px，落在可见区外。
2. 保持输入焦点，可见高度从 844px 变为 800px，变化不足旧阈值；输入框底边仍为 834px。

普通动画和减少动画模式均复现。问题是把键盘状态判断当成几何定位条件；仅改 padding 无法解决。对应的真实函数单元回归也在修复前失败：失焦后位移错误地从 344px 变为 0px。
