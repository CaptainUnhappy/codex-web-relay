# 历史提问与当前待答状态分离

验收时间：2026-10-19 09:20，Asia/Taipei。

## 根因与范围

用户报告 App 已无卡片，而 Web 仍显示“问题 · 在 App 中回答”。公网接口仍返回 `desktop-question:call_fb93f36bdc9040dcb7dbb629398ed4e5`；来源是会话 `01a137c2-71a0-76f0-a3d4-ae5e9bf39117` 的历史记录。没有找到该问题的明确回答或撤回记录，但这不能证明 App 当前仍显示它。

此前 `1e2d2f0`、`5d6c90b` 分别修正历史清理与自动消息误清除，都未补足 App 本地卡片关闭状态的权威来源。不能将这两次修复或 Web 页面一致性测试称为 App 原生卡片实时同步已经实现。

用户本轮明确选择：收进可展开的“历史提问”，标记“状态未确认”；统一提问服务保持隔离。

## 实现

- 服务端 `approvals` 只保留原生待处理请求。历史 App 问题独立返回为 `desktopQuestions`，附带 `stateSource: rollout-history`、`currentState: unknown`、`canSubmit: false`。
- Web 用独立的历史区域展示，不设置为 `currentApproval`，不发出待处理提醒。默认收起，展开可查看原问题与选项，并说明“以下来自对话历史，无法确认 App 中是否仍可回答”。
- 保留原有卡片内容样式、键盘展开、触摸滚动；轮询保留展开状态，切换会话或重新打开页面默认收起。真实原生提问与历史并存时，原生问题仍可正常回答并保留草稿。
- 新页面兼容旧服务器把历史混入 approvals 的响应；旧页面接入新服务器时也不会再将历史当作当前待答项。App 回答旁路继续被服务端拒绝。

## 手动关闭与恢复（2026-10-19 09:34）

历史卡片新增右上角“×”，点击后整张卡片消失。关闭记录按站点、对话及问题 ID 存在当前浏览器，轮询、刷新、切换会话和断线重连不会重新打开它；新问题 ID 不受旧关闭记录影响。同一浏览器同站点的标签页通过 storage 事件同步关闭/恢复偏好，不宣称跨设备同步。

长按对话标题，在操作菜单中选择“重新显示历史提问”可以恢复。关闭/恢复只改变 Web 展示，不提交答案、不伪造 App 的已答或关闭状态。关闭按钮有 44×44 点击区域与键盘可访问名称，不影响消息草稿或原生回答草稿。

验证：新增浏览器断言先因缺少真实关闭按钮失败，完成实现后通过；覆盖关闭、刷新、切回对话、两个标签页、恢复、新问题展示与草稿保留。`npm.cmd run check` 全部通过。另在公网隔离浏览器上下文以 390×844 手机模拟视口、1280×900 桌面视口实际点击关闭与长按标题恢复，刷新和离线重连后保持隐藏；服务端历史仍为 unknown，未产生提交请求。未改动用户原浏览器的关闭偏好，未重启服务。
