# Web 提问卡片与 App 交互对齐

日期：2026-10-18，时间使用 Asia/Taipei（UTC+8）。

## 用户反馈与根因

用户确认 Web 中能看到提问，但选项显示为下拉框，与 Codex App 的展开编号选项不同。第二张截图还显示排队消息中的 `**Codex 提问**`、`**你的回答**` 标记。

上一轮只验证了回答能送达；没有以 App 截图中的交互方式作为验收条件。队列问题则来自将结构化回答转成 Markdown，再交给纯文本摘要渲染，导致内部格式直接显示。

## 本次结果

- 用可直接点击的编号选项替换下拉框，选中项高亮，保留选项说明。
- 自定义输入直接可见；填写自由文本会取消选项，点击选项会替换自由输入。
- 未回答时发送按钮禁用；支持方向键选择、Ctrl/Command+Enter 发送。刷新和失败重试保留当前选择及输入。
- 提供关闭和“稍后回答”，收起后可点“继续回答”恢复草稿。此操作不提交空答案，也不声称问题已解决。
- 队列与用户历史气泡显示单行问题摘要和回答正文，回答保留换行，特殊字符作为文字显示。
- 已排队问题只在队列中展示，不再重复显示第二张“回答已排队”卡片。
- 沿用 Web 深色主题与现有会话交付流程；没有加入无实际功能的麦克风或绕过写入锁。

## 回归与审查

`npm.cmd run check` 全部通过。`scripts/test-user-input.js` 增加历史回答结构化字段检查。

浏览器回归脚本为 `scripts/test-question-ui.js`，通过 Playwright `browser_run_code_unsafe` 的 `filename` 参数执行。它从当前 Web 读取生产 HTML，在独立 fixture 域名隔离请求，覆盖展开选项、代码块、直接自由输入、草稿保留、收起恢复、方向键、失败重试、原生提问、队列去标记、多行历史、3 个问题内部滚动，以及 320／390／1024 px 布局。此 fixture 检查与上述真实发送分别计数。

独立只读审查未发现确定性阻塞问题。最终更新服务前确认 Mini 无占用、无不确定操作，只重启本项目 Node 服务，保留 Codex App 和监督进程。

## 验证边界

本次对齐提问卡片与回答显示，不声称复制 App 的全部功能，也不声称 Web 回答后 App 内部卡片一定同步关闭。实际测试以 Web 显示、真实答案回显、队列清空和会话释放为准。
